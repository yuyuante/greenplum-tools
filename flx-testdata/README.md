# `_FLX` 測試資料製作與還原

執行環境：在本目錄執行 `python flx_testdata.py`，需安裝 `psycopg2`。資料庫連線別名取自 `C:\Users\peteryu\code\env\<別名>.txt`；密碼不寫入執行紀錄。

## 製作方式

1. **只處理欲測試函式用到的表**：以 `--sp` 指定函式，程式從目的庫讀出函式原始碼，並往下追蹤其呼叫的函式與引用的 view（逐層追到底），找出所有用到的 `_flx` 表；可再以 `--table` 補充。
2. **找來源區段**：在來源庫找出與欲測試日期範圍等長、起日為同一星期幾、且每張表至少有 1 筆資料的區段；有多段符合時取日期最近的一段。
3. **確認後匯入**：`apply` 先列出要移轉的資料資訊（欲測試日期、來源區段與平移天數、各表日期欄位、來源筆數與天數、目的端將被取代的筆數、引用路徑、略過的引用），輸入 `y` 才開始備份與匯入。
4. **平移匯入**：將來源區段的資料整批平移到欲測試日期範圍，平移天數為 7 的倍數，所以星期幾不變。

## 參數與指令

- `--start`、`--end`：**欲測試的資料日期範圍**，含首尾兩日，格式 `YYYY-MM-DD`。
- `--sp schema.函式`：欲測試的函式，可重複提供。
- `--table schema.table`：補充資料表，可重複提供；`--sp`、`--table` 至少須提供一項。
- `--yes`：`apply` 不詢問確認，直接匯入；非互動執行（排程、指令碼）時使用。
- `--source`、`--destination`：來源與目的資料庫連線別名，預設 `GPstage`、`GP178`。
- `--manifest`：`apply` 產生的執行紀錄，用於 `verify`、`restore`。

```powershell
python flx_testdata.py plan --start 2026-06-16 --end 2026-06-19 --sp db_owner.<函式> --source GPstage --destination GP178
python flx_testdata.py apply --start 2026-06-16 --end 2026-06-19 --sp db_owner.<函式> --source GPstage --destination GP178
python flx_testdata.py verify --manifest flx_runs/<執行紀錄>.json --destination GP178
```

`plan` 只列出要移轉的資料資訊，不異動資料；`apply` 在每張表匯入前，先將目的日期區間的原資料備份到 `db_owner_temp.flxb_*`。備份保留至還原完成。目的資料相同日期區間已有資料時會以來源資料取代。執行紀錄存於 `flx_runs`，內含來源區段、平移天數、各表數量、備份表及資料指紋；不可刪除，否則難以還原。相同目的資料庫內有尚未還原的重疊日期執行時，程式會拒絕再次匯入。

測試結束後，以執行紀錄還原目的端原資料：

```powershell
python flx_testdata.py restore --manifest flx_runs/<執行紀錄>.json --destination GP178
```

若測試過程改動了匯入區間的資料，還原指令會因資料指紋不同而停止。確認可捨棄這些測試後變更時，加上 `--allow-changes` 再執行。還原按表提交；途中停止時，重新執行會從執行紀錄中尚未還原的表繼續。全部還原完成後會自動刪除本批備份表；若刪除途中失敗，對同一執行紀錄重新執行 `restore` 即可補刪。

## 使用限制

- 下列情況程式會停止並一次列出原因，不會略過缺表繼續匯入：欲使用的表兩端結構不同、無法選出單一日期基準欄位、來源庫沒有資料、只存在目的庫、未加 schema 且對應多個來源表、加了 schema 的函式呼叫在目的庫不存在、來源區段內有不合法的日期基準值，或找不到每張表都有資料的來源區段。
- `--sp` 追蹤方式：
  - 先去除字串外的 `--`、`/* */` 註解（區塊註解可巢狀；一般字串、`E'...'` 字串、`$$...$$`／`$tag$...$tag$` 與 `"引號識別字"` 內的內容保留，所以動態 SQL 字串裡的表仍會比對），再以名稱比對原始碼；以字串拼接組出的物件名稱無法追蹤，請以 `--table` 補充。未加 schema 且查無對應的函式呼叫（例如內建函式）直接忽略。
  - 前綴是實際存在的 schema 時，只比對該 schema 的物件，不會改抓其他 schema 的同名物件。
  - 未加 schema（或前綴是別名）時依名稱對應：函式須後接括號；同名的函式或 view 在多個 schema 都有時全部追蹤；`_flx` 表對應多個 schema 時，以 `--table` 指定其中一張即可。
  - 以名稱比對可能多抓：`別名.欄位` 剛好與 `_flx` 表同名、只用來宣告變數型別的表（如 `v_rec db_owner.x_flx;`、`%type`／`%rowtype`）、同名函式的所有版本（參數不同）、多個 schema 的同名 view 都會被納入。多抓的表若無法處理，程式會停止並列出引用路徑，可據此判斷。
  - 兩庫都沒有的 `_flx` 名稱（例如暫存表），以及存在但不在處理範圍（schema 不是 `db_owner`／`cr_admin`／`db_owner_temp`，或不是一般資料表）的 `_flx` 物件，列在「略過的引用」並註明原因。
- 「至少有 1 筆」是以整個區段判斷，不保證區段內每一天各表都有資料。平移天數為 7 的倍數，可讓星期幾一致，但國定假日仍可能不同。
- 日期欄位：`date`、`timestamp` 型別，以及名稱符合日期命名規則的 `char`／`varchar(8)`（`YYYYMMDD`）或 `char`／`varchar(10)`（`YYYY-MM-DD`）；`text` 或未限長度的 `varchar` 不視為日期欄位。所有日期欄位都以相同天數平移；字元型欄位的不合法值（如 `20250631`、`00000000`、空白）與 9999 年的值（如 `99991231`，視為「永久有效」的代表值）保留原值；找來源區段時也不計 9999 年的日期。
- 舊版（以 `--years` 平移）的執行紀錄只支援對已還原批次補刪備份表。還原與刪除備份表前（連線資料庫之前），會先檢查執行紀錄檔名須等於本批編號，且整批備份表名稱須為 `db_owner_temp.flxb_<本批編號>_<序號>`，不符時不連線、不執行任何異動。

執行期間請避免其他工作同時修改目的日期區間。程式使用資料庫鎖阻止另一個相同工具同時執行，但無法阻止其他 SQL 工作；`verify` 與還原時的資料指紋檢查用於發現這類變動。
